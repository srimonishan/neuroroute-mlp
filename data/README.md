## 1. Problem Formulation & Data Pipeline (Member 1 – Harsha Bhagya)

### 1.1 Formal Problem Formulation (TSP)
The Travelling Salesperson Problem (TSP) is formulated as a sequential multi-class classification task on a complete, undirected weighted graph $G = (V, E)$, where $V = \{0, 1, \dots, n-1\}$ denotes the set of cities and $E$ represents the edges weighted by a supplied symmetric distance matrix $D \in \mathbb{R}^{n \times n}$.

* **Input:** At each decision step $t \in \{0, 1, \dots, n-2\}$, the MLP receives a state representation vector $x_t \in \mathbb{R}^{3n}$ encoding the current city, the set of previously visited cities, and the normalized travel costs from the current city to all cities.
* **Output:** A probability distribution $\hat{y}_t \in \mathbb{R}^n$ over all $n$ cities, predicting the next valid city $v_{t+1} \in V$ to visit.
* **Constraints:**
  1. Each city $v \in V$ must be visited exactly once (Hamiltonian cycle).
  2. Every tour starts at city `0` and returns to city `0` after visiting all $n$ cities.
  3. During tour decoding/inference, already visited cities are masked out to enforce route validity.
* **Objective Function:** Minimize the total closed-tour distance $C(\pi)$ for a city permutation $\pi$:
  $$C(\pi) = \sum_{k=0}^{n-2} d(\pi[k], \pi[k+1]) + d(\pi[n-1], \pi[0])$$

### 1.2 Dataset Audit & Baseline Validation
The supplied raw dataset (`tsp_data_100_distance_matrix.csv`) was audited using `src/data/data_pipeline.py` prior to feature extraction:
* **Dimensions & Completeness:** A $100 \times 100$ square matrix (`100` cities, `City_0` to `City_99`) containing `0` missing (`NaN`), infinite, or negative values, and `0` duplicate city rows.
* **Symmetry & Diagonal:** Strictly symmetric ($D = D^T$, `True`) with all diagonal entries equal to `0.0` ($d(i,i) = 0$). Off-diagonal distances range from a minimum of `0.63` to a maximum of `126.80`, with a mean of `53.60`.
* **Non-Euclidean Properties:** Validation identified `226` directed (`113` undirected) triangle inequality violations ($d(i,j) > d(i,k) + d(k,j)$). These reflect realistic non-Euclidean routing conditions and were preserved without modification.
* **Full 100-City Heuristic Baseline:** Running Nearest Neighbour (NN) from `City_0` yielded a valid tour length of **991.46**, which was subsequently improved by 2-opt local search to **831.64** (`Valid tour: True`).

### 1.3 Synthetic Instance Generation, Symmetry Breaking & Feature Engineering
Because a single 100-city instance produces only 99 decision steps—insufficient for training and evaluating an MLP—`500` synthetic sub-problem instances of fixed size $n = 20$ cities were generated by sampling subsets of cities without replacement from the $100 \times 100$ matrix (`SEED = 42` for reproducibility).

1. **Reference Label Generation & Canonical Direction:** For each $20$-city instance, a reference tour was computed using Nearest Neighbour followed by 2-opt optimization. To eliminate equivalent tour representations and conflicting supervision labels:
   * Tours were rotated to always begin at local city `0`.
   * A canonical direction rule (`tour[1] < tour[-1]`) was enforced so clockwise and counter-clockwise equivalents map to a single consistent sequence.
2. **State Feature Representation ($3n = 60$ dimensions):** Each $20$-city tour was decomposed into $n - 1 = 19$ step-level samples. At step $t$, the feature vector $x_t \in \mathbb{R}^{60}$ was formed by concatenating:
   * **Current City One-Hot Vector ($20$ dims):** Binary indicator of the current city.
   * **Visited City Mask ($20$ dims):** Binary mask (`1` for cities visited up to step $t$, `0` otherwise).
   * **Normalized Distance Vector ($20$ dims):** Distances from the current city to all $20$ cities, scaled to $[0, 1]$ by dividing by the maximum distance within that specific instance (`sub.max()`).

---

### 1.4 Leakage-Safe Data Partitioning & Deliverables
To prevent data leakage—where consecutive steps of the same tour appear in both training and evaluation splits—the `500` instances were partitioned **at the instance level** prior to step decomposition:
* **Training Set (70%):** `350` instances $\rightarrow$ `6,650` samples (`X_train`: `(6650, 60)`, `y_train`: `(6650,)`).
* **Validation Set (15%):** `75` instances $\rightarrow$ `1,425` samples (`X_val`: `(1425, 60)`, `y_val`: `(1425,)`).
* **Test Set (15%):** `75` instances $\rightarrow$ `1,425` samples (`X_test`: `(1425, 60)`, `y_test`: `(1425,)`).

The processed arrays, held-out test distance matrices (`test_matrices`, `test_tours`), and the instance split manifest (`train_city_idx`, `val_city_idx`, `test_city_idx`) were exported to `data/processed/processed.npz`.
